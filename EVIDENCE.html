Technical Evidence

Proof-of-Solvency for Tokenized Private Credit

A fund proves it is solvent and fully KYC'd, over a loan book it cannot fake, without revealing a single loan. Every claim below is measured and independently verified.

What it is

An open-source zero-knowledge verifier. A Groth16/BN254 circuit proves, over a PRIVATE loan book, that (1) performing collateral covers the required over-collateralisation of the token supply, (2) every borrower passed KYC, and (3) the book hashes to a servicer-signed hiding commitment. Only the threshold and the commitment are revealed. The mint is gated on the proof and the servicer signature together, so a prover cannot substitute a different book.

Independent verification (audited three ways)

1. Empirical adversarial audit (cargo run --bin audit): checks that fail if the ZK claims were fabricated. Result: the circuit genuinely enforces solvency, all-KYC, and commitment binding; insolvent, KYC-fail, and wrong-commitment books each fail the constraint system; a proof with one flipped bit or an altered public input is rejected. Passed.

2 & 3. Two independent code reviews. Two separate reviewers read every source file. Verdict: "genuine, working ZK cryptography, not fabricated or hollow." The second review, after fixes, confirmed: "genuinely in a more honest and sounder state than before; documentation matches what the code enforces." The full record is in AUDIT.md.

Reproducible

One command reproduces every claim above: ./demo.sh runs the statement soundness tests, realistic loan-tape decisions (mint allowed / blocked), the ZK proof, the on-chain mint-gate plus the attack test, the scale benchmark, and the real on-chain compute-unit measurement. Deployed and confirmed on a live Solana validator (program success, confirmed transaction signature). MIT-licensed.

What is NOT yet production-safe (stated honestly)

  • Trusted setup is not yet fully multi-party. A phase-2 (delta) ceremony is implemented and validated; a complete ceremony additionally needs a multi-party phase-1 (Powers of Tau) and contribution proofs.
  • Not third-party security-audited. Independently code-reviewed, but not a formal security audit.
  • The data-trust anchor is external. A proof certifies that the servicer-attested data is solvent, not that the data is true. It depends on an authenticated signed loan-tape feed.

Full detail: KNOWN_LIMITATIONS.md. This is a research prototype, not a production system.
